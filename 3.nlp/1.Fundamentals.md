
<h1 align="center">Text Preprocessing</h1>

---

1. Text Cleaning

Definition: Removing unwanted characters, symbols, or formatting to normalize raw text.
Why: Raw text (tweets, reviews, medical notes) is noisy → cleaning improves model accuracy.

Steps:
Lowercasing
Removing punctuation, special symbols
Handling extra spaces, HTML tags, numbers, emojis (depending on task)

Real-world use case:
In sentiment analysis of tweets, removing hashtags, mentions, links, and emojis before feeding into a model.
In healthcare clinical notes, removing patient IDs and symbols.



```python
import re

text = "Hello!!! This is NLP, 2025 🚀. <br> Let's start." #re.sub search and replace
cleaned = re.sub(r"<.*?>", "", text)   # remove HTML
cleaned = re.sub(r"[^a-zA-Z\s]", "", cleaned)  # remove punctuation/numbers/emojis
cleaned = cleaned.lower().strip()

print(cleaned)
# Output: "hello this is nlp lets start"
```

2. Tokenization

Definition: Splitting text into smaller units (tokens) like words, subwords, or characters.
Why: Models cannot directly understand text → tokens act as the input units.

Types:
Word-level: Split on spaces → "I love AI" → ["I", "love", "AI"]
Problem: Out-of-vocabulary (OOV) words.
Subword-level (BPE, WordPiece, SentencePiece)
"unhappiness" → ["un", "happiness"]
Reduces OOV problem → used in BERT, GPT.
Character-level: "AI" → ["A", "I"]
Used in spelling correction, OCR.

Real-world use case:
Search engines → split queries into tokens for indexing.
BERT/GPT → subword tokenization to efficiently handle huge vocabularies.



```python
import os
```

3. Stop Words Removal

Definition: Removing frequently occurring but less informative words like “the”, “is”, “and”.
Why: They may add noise in classical ML models (e.g., TF-IDF, BoW).
Real-world use case:
In search ranking, ignoring stop words prevents unnecessary matches.
In clinical text mining, removing “patient was given” type fillers.
👉 Note: In transformer models, stop words are usually kept, since context matters.


```python
from nltk.corpus import stopwords
nltk.download('stopwords', quiet=True) #nltk_data\corpora\stopwords

text = ["this", "is", "a", "sample", "sentence"]
filtered = [w for w in text if w not in stopwords.words("english")]
print(filtered)
# ['sample', 'sentence']
```

4. Stemming vs Lemmatization
Definition: Reducing words to root/base forms.
Stemming: Rule-based chopping → "playing" → "play" (sometimes "studies" → "studi")
Lemmatization: Dictionary + grammar-based → "studies" → "study"

Real-world use case:
Search engines use lemmatization (better results).
Topic modeling may use stemming (faster, but less precise).
👉 Interview tip: Say lemmatization is preferred in modern NLP pipelines for accuracy.



```python
from nltk.stem import PorterStemmer, WordNetLemmatizer
nltk.download('wordnet', quiet = True)

stemmer = PorterStemmer()
lemmatizer = WordNetLemmatizer()

print(stemmer.stem("studies"))   # studi
print(lemmatizer.lemmatize("studies"))  # study
```

6. Part-of-Speech (POS) Tagging

Definition: Assigning grammatical roles (noun, verb, adjective) to words.
Why: Helps in understanding syntax & meaning.

sentence: "The cat sat on the mat"
POS tags: [DET, NOUN, VERB, ADP, DET, NOUN]

Real-world use case:
Question answering → identify verbs (action) vs nouns (entity).
Chatbots → grammar-based intent detection.




<h1 align="center">Classical Representations</h1>

---

## 1. Bag of Words (BoW)

**Definition**  
BoW represents text as a “bag” of words, ignoring grammar and order, just counting word frequency.  
It converts text into a fixed vector based on word occurrence.

**How it works**  
1. Build a vocabulary of all unique words in corpus.  
2. Represent each document as a vector of word counts.

**Example**  
Corpus:  
Doc1: "I love NLP"  
Doc2: "I love AI"  

Vocabulary = [I, love, NLP, AI]  

Vectors:  
Doc1 → [1, 1, 1, 0]  
Doc2 → [1, 1, 0, 1]


```python
from sklearn.feature_extraction.text import CountVectorizer

docs = ["I love NLP", "I love AI"]
vectorizer = CountVectorizer()
X = vectorizer.fit_transform(docs)

print(vectorizer.get_feature_names_out())
# ['ai' 'love' 'nlp']
print(X.toarray())
# [[0 1 1]   -> "I love NLP"
#  [1 1 0]]  -> "I love AI"
```

**Pros**
- Simple and interpretable  
- Works surprisingly well for small datasets  

**Cons / Limitations**
- Ignores word order (semantics lost)  
- Produces high-dimensional sparse vectors  
- Treats all words equally (no weighting)  

**Real-world use cases**
- Early spam detection (counting spammy words)  
- Document similarity in early search engines  
---


## 2. TF-IDF (Term Frequency – Inverse Document Frequency)

**Definition**  
TF-IDF improves BoW by down-weighting common words and up-weighting rare but informative words.  

### Formulas

**Term Frequency (TF):**  
$$
TF(t, d) = \frac{\text{count of term } t \text{ in document } d}{\text{total terms in document } d}
$$

**Inverse Document Frequency (IDF):**  
$$
IDF(t) = \log \frac{N}{DF(t)}
$$

Where:  
- $N$ = total number of documents  
- $DF(t)$ = number of documents containing term $t$  

**Combined:**  
$$
TFIDF(t, d) = TF(t, d) \times IDF(t)
$$

### Intuition
- Very frequent words across all documents (“the”, “is”, “and”) → low IDF → low weight  
- Rare, domain-specific words (“transformer”, “diabetes”, “Elon Musk”) → high IDF → high weight  

### Example (Python)
```python
from sklearn.feature_extraction.text import TfidfVectorizer

docs = ["I love NLP", "I love AI", "AI is the future of NLP"]
vectorizer = TfidfVectorizer()
X = vectorizer.fit_transform(docs)

print(vectorizer.get_feature_names_out())
print(X.toarray())
```


# Variants of IDF

## Smoothed IDF
$$
IDF(t) = \log \frac{1 + N}{1 + DF(t)} + 1
$$
Prevents divide by zero.

## Sublinear TF Scaling
Use:
$$
1 + \log(TF)
$$
instead of raw counts.


# Pros
- Simple, fast, interpretable  
- Highlights domain-specific words  
- Robust baseline for text classification  

# Cons / Limitations
- Sparse, high-dimensional  
- No semantic meaning (doctor ≠ physician)  
- Ignores word order/context  

# Real-world Use Cases
- Search engines → early Google ranking  
- News classification → categories like “sports” vs “politics”  
- Medical/legal retrieval → highlight terminology  
- Spam filtering → spammy words get higher weights  

# When NOT to Use TF-IDF
- In transformer-based NLP pipelines (contextual embeddings are superior)  
- When semantic similarity across synonyms is required  

# Comparison with Embeddings
- **TF-IDF**: interpretable, lightweight, strong baseline  
- **Embeddings (Word2Vec, BERT)**: capture semantics, synonyms, context  

# Interview Soundbite
“TF-IDF balances word frequency with importance. It penalizes common words and highlights rare, informative terms. Today, embeddings outperform it semantically, but TF-IDF is still used in industry for baseline ranking and keyword-based search.”

# 3. N-gram Models

## Definition
N-grams capture sequences of N words (instead of treating words independently).

## Examples
- **Unigram (N=1):** `"I"`, `"love"`, `"AI"`  
- **Bigram (N=2):** `"I love"`, `"love AI"`  
- **Trigram (N=3):** `"I love NLP"`  
- **4-gram (N=4):** `"This is the house"`  

## Example (Python)
```python
from sklearn.feature_extraction.text import CountVectorizer

# Extract bigrams
vectorizer = CountVectorizer(ngram_range=(2, 2))
X = vectorizer.fit_transform(["I love NLP models", "NLP models are powerful"])

print(vectorizer.get_feature_names_out())
# Output: ['love nlp' 'nlp models' 'models are' 'are powerful']
```

# Probability Formulation (Markov Assumption)

The probability of the current word depends only on the last *k* words:

$$
P(w_n \mid w_{n-1}, ..., w_{n-k}) =
\frac{C(w_{n-k}, ..., w_n)}{C(w_{n-k}, ..., w_{n-1})}
$$

## Example

$$
P(\text{house} \mid \text{this is the}) =
\frac{C(\text{this is the house})}{C(\text{this is the})}
= \frac{1}{4}
$$

# Pros
- Captures local context that BoW/TF-IDF miss  
- Effective for short-phrase modeling (e.g., “not good” vs “good”)  

# Cons / Limitations
- Vocabulary explosion with higher N  
- Data sparsity (need smoothing: Laplace, Good-Turing, Kneser-Ney)  
- No long-range dependencies  
- Outperformed by RNNs and Transformers  

# Real-world Use Cases
- Autocomplete → predicting next word  
- Speech recognition → statistical language models  
- Early machine translation  
- Sentiment analysis with negations  

---

# Interview Q&A

**Q: How do you handle zero probabilities in N-grams?**  
A: Use smoothing techniques (Laplace, Good-Turing, Kneser-Ney).  

**Q: Why did we move beyond N-grams?**  
A: Because they can’t capture long-range dependencies or semantic similarity.  

**Q: Why do transformers outperform N-grams?**  
A: They capture global context and avoid sparsity issues.  

# Quick Comparison

| Method      | Strengths                           | Weaknesses                          |
|-------------|-------------------------------------|--------------------------------------|
| **BoW**     | Simple, interpretable               | Sparse, ignores order                |
| **TF-IDF**  | Highlights rare words, strong base  | Sparse, no semantics                 |
| **N-grams** | Captures short context              | Data sparsity, vocab explosion       |
| **Embeddings** | Dense, semantic, context-aware   | Heavier compute, less interpretable  |

# Final Interview Tip
“BoW counts words, TF-IDF weights them, N-grams add short context, embeddings add semantics.  
For quick baselines TF-IDF is still used, but embeddings (Word2Vec, BERT) dominate modern NLP.”
